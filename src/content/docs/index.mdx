Write specs in TypeScript. Check every order in which things can happen. Then check your real code against the spec.

## The problem

Some of the worst bugs are not in any one function. They are in the order of events: a retry that lands while the
first attempt is still running, two workers reading the same row, an async reply that arrives after the user already
changed something, a webhook delivered twice, a long-running workflow or an AI agent deciding at runtime which step
comes next.

Tests run the orders someone thought of. The bug is usually in an order nobody did. Tools that check every order exist,
like TLA+ and Quint, but they ask you to learn a second language and model the system again, away from the code.

## What it does <a id="what-it-does" />

<CardGrid>
	<Card title="Specs in plain TypeScript">

		The checker walks every state the spec can reach and reports the shortest sequence of steps that breaks a rule.

## Where it fits

- Compared with TLA+ and Quint: the same kind of exhaustive checking, without a second language, and with a direct
  check of the real code. See [Other non-TypeScript Tools](/tools/speccraft-vs-non-ts-tools).
- Compared with fast-check and other property-based testing: every state, not a random sample of them. See
  [Other TypeScript Tools](/how-speccraft-compares) for the full map of TypeScript tools.
- Next to proof tools: Lean and Dafny prove one function right for every input. SpecCraft checks the order of events
  between steps. They work well together. The guides show how to use each from a TypeScript project:
  [Lean](/tools/lean), [Dafny](/tools/dafny), [Quint](/tools/quint).

## Where it started

SpecCraft started from a Temporal workflow that grew too hard to reason about, and a two-page formal spec that made it
clear again. That research, on durable execution and its correctness problems, is in the
[Durable execution](/durable-execution-problems) pages. The same problem shows up anywhere events can interleave, so
SpecCraft now aims to be a general TypeScript tool.

## Status

SpecCraft is a work in progress and not ready to use yet. Right now the work is research (collecting what exists and
what people need) and a proof of concept. The proof of concept is on
[GitHub](https://github.com/orgs/speccraft-io/repositories) and on npm as
[`@speccraft-io/core`](https://www.npmjs.com/package/@speccraft-io/core), as an experiment, not a release. Drop your
email to hear when there is something to try, and to help shape what gets built.
