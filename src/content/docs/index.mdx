Formal methods for TypeScript: the concepts, the tools that exist, and how to use them from a TypeScript project.

## The problem

Some of the worst bugs are not in any one function. They are in the order of events: a retry that lands while the
first attempt is still running, two workers reading the same row, an async reply that arrives after the user already
changed something, a webhook delivered twice, a long-running workflow or an AI agent deciding at runtime which step
comes next.

Tests run the orders someone thought of. The bug is usually in an order nobody did. Formal methods are the tools that
check every order, or prove a function right for every input. Most of them live outside TypeScript, and a growing
number now work from inside it. This site maps both and shows how to use them.

## Where it started

This research started from a Temporal workflow that grew too hard to reason about, and a two-page formal spec that
made it clear again. That work, on durable execution and its correctness problems, is in the
[Durable execution](/durable-execution-problems) pages. The same problem shows up anywhere events can interleave, so
the site now covers TypeScript in general.
