## Can a retried webhook charge the card twice?

The first delivery is slow, so the sender retries. Two workers get the two deliveries. Both read `unpaid` before
either one writes `paid`, and both charge the card.

<CodeFix before={quintBefore} after={quintAfter} title="src/webhook.ts" />

**Found with Quint.** `quint verify` checks every state of a model with two workers and two deliveries, and prints
the order of steps that charges twice. The fix makes the read and the claim one step, as a conditional
`UPDATE ... WHERE status = 'unpaid'` in the database.

Full walkthrough: [Quint for TypeScript developers](/tools/quint)

## What if the approval and the 24h timeout fire at the same time?

A manager approves a payment hold while the 24h timer fires. Both handlers read `settled = false` before either one
sets it. The money is captured and released.

<CodeFix before={tlaBefore} after={tlaAfter} title="src/payment-hold.ts" />

**Found with TLA+.** TLC finds the race in 13 states. The obvious fix, setting the flag before the `await`, removes
the race but leaves the hold stuck forever when the card is declined. TLC finds that too, with a liveness check. The
final version releases the hold itself when the capture fails.

Full walkthrough: [TLA+ for TypeScript developers](/tools/tla-plus)

## Can this discount make the price negative?

Nothing stops `percent` from being over 100. The discount is then bigger than the price, unless the cap happens to
catch it.

<CodeFix before={leanBefore} after={leanAfter} title="src/pricing.ts" />

**Found with Lean.** The proof that the result is never negative fails, and Lean shows the kind of input that breaks
it. After the clamp, three rules are proven for every whole-number input. The proof also shows a precondition nobody
wrote down: a negative cap makes the price go up.

Full walkthrough: [Lean for TypeScript developers](/tools/lean)

## Does this binary search find every id?

Tests for a found id and a missing id both pass. But `indexOfId([10, 20, 30], 10)` returns `-1`. When the search
narrows down to one last element, the loop stops before looking at it.

<CodeFix before={dafnyBefore} after={dafnyAfter} title="src/ids.ts" />

**Found with Dafny.** The verifier cannot prove that `return -1` means "the id is not in the list", and points at
that line. With `while lo <= hi` it proves the function for every sorted list and every target, and compiles the
proven code to JavaScript you import from TS.

Full walkthrough: [Dafny for TypeScript developers](/tools/dafny)
