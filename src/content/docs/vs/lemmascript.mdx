[LemmaScript](https://github.com/midspiral/LemmaScript) is a verification toolchain for TypeScript,
currently a tech preview. It is the most serious
"formal methods for TypeScript" project we know of.

<Short>LemmaScript turns `//@` contract comments into Dafny proofs. Here: a bill split with a rounding bug.</Short>

## Using LemmaScript

The code below is in
[formal-methods-samples/lemmascript-split-bill](https://github.com/speccraft-io/speccraft-io/tree/main/formal-methods-samples/lemmascript-split-bill). We ran it with `lsc` 0.6.4 and Dafny 4.11.0.
The output is from our run.

### The problem

<Short>Rounding every share up can leave the last person with a negative share.</Short>

A bill in cents is split between people. Everyone pays the same share, rounded up so nobody underpays, and the last
person pays what is left:

```ts
// splitBill.ts (shortened)
export function splitBill(total: number, people: number): Split {
  const each = Math.ceil(total / people);
  const last = total - each * (people - 1);
  return { each, last };
}
```

For 1,000 cents between 3 people it gives 334, 334 and 332, and the shares add up. But when the shares are small
and there are many people, rounding up takes more than the whole bill before the last person is reached.

### Install and set up

```sh
npm install -D lemmascript
```

Needs Node 18+ and Dafny 4+ (this page does not use the Lean backend).

### Writing the contract

<Short>`//@ requires` and `//@ ensures` state the contract inside the TS file.</Short>

A contract is a set of `//@` comments inside the ordinary TypeScript. `tsc` and the bundler ignore them.

```ts
// splitBill.ts
//@ verify
export function splitBill(total: number, people: number): Split {
  // What callers must pass.
  //@ requires total >= 0
  //@ requires people >= 1
  // What the function promises; \result is the return value.
  //@ ensures \result.each * (people - 1) + \result.last === total
  //@ ensures \result.last >= 0
  //@ ensures \result.each >= 0
  const each = Math.ceil(total / people);
  const last = total - each * (people - 1);
  return { each, last };
}
```

### Running it

<Short>Dafny cannot prove `last >= 0`. One failing input: 20 people splitting 3.41.</Short>

`lsc gen` translates the file, and `lsc check` regenerates it and runs Dafny:

```sh
lsc gen --backend=dafny src/splitBill.ts
lsc check --backend=dafny src/splitBill.ts
```

The generated Dafny follows the TypeScript: the interface becomes a datatype, `Math.ceil` a helper over real
numbers, and each `//@` line a Dafny clause:

```text
// splitBill.dfy (shortened)
function splitBill(total: int, people: int): Split
  requires (total >= 0)
  requires (people >= 1)
{
  var each := CeilReal(((total as real) / (people as real)));
  var last := (total - (each * (people - 1)));
  Split(each, last)
}

lemma splitBill_ensures(total: int, people: int)
  requires (total >= 0)
  requires (people >= 1)
  ensures (((splitBill(total, people).each * (people - 1)) + splitBill(total, people).last) == total)
  ensures (splitBill(total, people).last >= 0)
  ensures (splitBill(total, people).each >= 0)
{
}
```

The exit code is 1, so the same command fails a CI job. The shares always add up (that holds by construction), but
the last share can be negative. Dafny does not say for which input. One is 20 people splitting 3.41: each share is
0.18, and the last person is owed 0.01.

### Fixing the bug

<Short>Round down with `Math.floor`. Proved for every input.</Short>

The fix: rounding down leaves the remainder for the last person, which is never negative:

Dafny proved it with no help: the contract now holds for every total and every number of people, not for sampled
ones.

### Tips

- **Read which promise failed, then find the input.** A failure names the clause and its line in the generated
  Dafny, not an input that breaks it.

## Strengths and limits

| | LemmaScript |
|---|---|
| Question it answers | Is this function correct for every input? |
| Technique | Deductive proof (Dafny / Lean) |
| Best fit | A pure domain core: reducers, splitters, permission checks, parsers |
| What you get back | A proof, or a failed proof obligation |
| Bounds | None: all inputs |
| Toolchain | TypeScript plus Dafny or Lean, and an LLM for the proofs |

- **LemmaScript covers all inputs, and data.** Money that never goes missing, sums, rankings, graph reachability: properties
  over real-sized values are what a proof handles and a bounded search cannot. It is also more mature, with many
  case studies, a VS Code extension and a CI workflow.
- **It does not cover the order of events or I/O.** Dafny proves sequential code; it has no notion of three async
  jobs in flight or a reply arriving between a check and its write. The case studies prove the pure core and leave
  the UI, network, Durable Objects and WebSockets unverified. For event order, a model checker such as
  [TLA+](/tools/tla-plus), [Quint](/tools/quint) or [pnueli](/vs/pnueli) explores every ordering in a bounded model.
- **There is a translation in between.** The TypeScript is translated to [Dafny](/tools/dafny) or [Lean](/tools/lean),
  so you install that toolchain and trust the translation. Numbers become ideal integers and division is exact, where
  JavaScript uses floating point. A failure comes back as a proof obligation, not a concrete trace.
- **It is a tech preview.** Some TypeScript methods, unions and narrowing patterns are not supported yet; the guide
  expects you to fix some of them in LemmaScript itself.
- **Worth copying:** contracts as comments, one file list for local runs and CI, and generated files that may only
  gain additions.
